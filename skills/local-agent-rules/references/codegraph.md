# CodeGraph 索引维护

本流程针对已安装 CodeGraph 的本机项目。先核对 `codegraph --version` 和当前版本的 `--help`；字段缺失、格式不匹配或状态不明确时，不假定索引最新。

## 1. 确认项目与工作树

1. 解析当前任务实际操作的项目绝对路径；Git 项目可使用 `git -C "项目绝对路径" rev-parse --show-toplevel` 确认工作树根目录。
2. 允许项目已有的子项目索引布局，不为所有父目录或其他仓库建立索引。
3. 未建立索引且没有初始化授权时，直接使用常规工具，不调用无关项目的 MCP 索引。
4. Git worktree 必须核对索引归属，不能把主 checkout 的索引当成本 worktree 的代码。

## 2. 检查状态

```sh
codegraph status --json "项目绝对路径"
```

在本会话首次依赖该项目索引前执行；切分支、pull/merge/rebase、批量改代码或工具提示过期后，再次使用前重新检查。持续有新修改时，不因之前检查通过就永久信任索引。

核对以下字段及当前版本提供的诊断：

- `initialized`：是否初始化。
- `projectPath`：实际索引范围。
- `worktreeMismatch`：是否借用了另一个工作树的索引。
- `pendingChanges.added/modified/removed`：源码与索引的差异。
- `index.state`：当前版本报告的完整性状态。
- `index.pendingRefs`：是否有待解析调用关系。
- `index.reindexRecommended`：是否建议按新版本重新构建。

`status` 也可能失败、输出非 JSON、遇到锁或返回旧版本字段；这些都不是“最新”的证据。

## 3. 选择最小更新动作

| 状态 | 动作 |
|---|---|
| 未初始化 | 默认常规工具；用户授权且当前权限允许时 `init` |
| 索引属于其他 worktree | 不使用错误索引；在当前 worktree 授权初始化或退回源码 |
| 状态完整、无待同步变更、无待解析引用 | 可以查询，无需重建 |
| 普通源码增删改、切分支后有差异、存在待解析引用 | `sync`，然后复查 |
| `indexing` 或写锁占用 | 先检查活动进程和状态，不能并发构建 |
| 确认失败、不完整或上次构建中断且没有活动索引进程 | `index`，然后复查 |
| 明确建议重建 | 结合版本说明执行一次 `index`，不能每次查询都重建 |
| 状态无法确认、读写受限或更新失败 | 说明限制，直接读源码，不依赖旧调用链 |

命令分工：

```sh
codegraph init "项目绝对路径"   # 首次初始化并建立索引，需要初始化授权
codegraph sync "项目绝对路径"   # 增量同步，普通修改和切分支的首选
codegraph index "项目绝对路径"  # 全量重建，不是日常默认动作
```

不要仅因 `.codegraph/` 目录存在就认定数据库完整。不要用 `--force` 绕过主目录或根目录保护，不删除锁文件，不擅自运行 `unlock`，不停止其他会话的索引进程。

## 4. 更新后验证

- 必须等待更新命令完成，再执行 `status --json`。
- 确认索引路径正确、无 worktree 错配，完整性状态正常；若仍有 pending 变更，检查是否持续有编辑或后台同步。
- 不把零变更输出或退出码为 0 单独当作成功：某些版本的锁竞争可能表现为无操作，需要结合复查结果。
- 若仍不确定，不忙等、不无限重试、不堆叠并发任务；改读源码并说明索引暂不可用。
- 函数行号、调用链、影响范围可能在代码继续变化时再次过期；编辑前以实际源码核对。

## 5. 自动更新的边界

- `init` 结束不等于常驻 watcher 启动。
- 自动增量同步依赖对应项目的 watcher 正常运行且未被关闭或降级。
- 分支切换改变的是工作区文件；watcher 可以捕获这些变化，但异步同步不保证切换瞬间完成。
- 能通过 `projectPath` 查询一个索引，不代表该项目已被持续监听。
- Git hooks 只能覆盖其配置的事件，不能替代任意未提交编辑的监听。
- 此 skill 只规定 Agent 使用索引前如何验证；需要后台保证时另行配置 watcher 或 hooks，不能自动覆盖已有 hooks。
